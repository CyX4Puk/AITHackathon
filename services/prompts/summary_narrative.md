# Промпт: краткий вывод по контрагенту

Отдельный вызов LLM после `analyze(inn, dealContext?)`. Вход — JSON из `signal_rules.md` §6 + срез `profile` + `dealContext` + последний запрос пользователя (если есть). Сырой отчёт не передавать.

## Готовая строка промпта (один контрагент)

```
Напиши краткий вывод по контрагенту для предпринимателя перед сделкой: 2–4 коротких абзаца, простым деловым языком.

Входные данные (единственный источник фактов):
{analyze_result_json}

Контекст сделки пользователя:
{deal_context_json}

Последний запрос пользователя (если релевантен акцентам):
{user_query}

Правила:
1. Используй ТОЛЬКО факты из signals, gaps и profile. Не добавляй чисел, дат и событий, которых нет во входе.
2. Метки baseInfo.riskLevel и zskRiskLevel — принимай как есть, не пересчитывай и не оспаривай.
3. Если riskLevel = UNKNOWN — скажи, что уровень риска в отчёте не определён; не объясняй метку выдуманными причинами.
4. Отсутствие данных (gaps) ≠ отсутствие риска — формулируй нейтрально.
5. Не выноси вердикт «не работать» / «однозначно надёжна». Допустимо: «стоит обратить внимание», «имеет смысл запросить», «по доступным данным выглядит устойчиво, но…».
6. Если задан dealContext (цель, сумма) — свяжи вывод с ним: соразмерность суммы, релевантность для поставки/госзакупки.
7. Не перечисляй все сигналы списком — выдели главное; детали останутся в карточках фактов ниже.
8. Последний абзац — мягкое напоминание, что решение за пользователем; ниже будут шаги проверки.

Формат ответа: только текст абзацев, без заголовков, без markdown, без технических путей полей.
```

## Режим compare (2+ контрагентов в сессии)

Отдельный вызов или ветка того же промпта. Вход — массив `analyze_result` по сессии + `dealContext`.

```
Напиши краткий вывод при сравнении контрагентов: одно–два простых предложения — кого выбрать под задачу пользователя.

Входные данные:
{analyze_results_json}

Контекст сделки:
{deal_context_json}

Правила:
1. Если dealContext пуст — НЕ давай рекомендацию. Спроси цель и сумму («поставка на 100 млн», «госзакупка» и т.п.).
2. Если контекст есть — назови, с кем логичнее начать, и кого оставить запасным. Одна короткая причина, без перечисления всех сигналов.
3. Опирайся только на факты из входа. Без баллов, без «мест» в рейтинге.
4. Допустимо: «начните с …», «остальные — с оговорками». Недопустимо: «однозначно не работать», «гарантированно надёжна».
5. Не дублируй предупреждения по статусу из alert над блоком.
6. Детали — в матрице; в ответе только выбор под задачу.

Формат: 1–2 предложения, без заголовков и markdown.
```

**Без контекста сделки:**

Для какой сделки сравниваете? Напишите цель и сумму — например: «поставка на 100 млн». Тогда подскажу, с кем логичнее начать.

**С контекстом (пример):**

Для поставки на 100 млн начните с Транслориума — самый спокойный профиль в сессии. Агилар СК и Техпром — с оговорками (долги и суды; высокий риск банка).

## Интеграция

- Показывать блок LLM (`plate` `llm-summary`, **без заголовка**) в ответ-сводке **после** оценки банка и **до** «Что проверить до сделки» (один контрагент) или после предупреждений по статусу (сравнение).
- Детерминированная часть сводки рендерится сразу (≤ 3 с); абзац LLM подставляется асинхронно или skeleton до 30 с.
- При недоступности LLM в режиме compare блок показывается с детерминированной рекомендацией; для одного контрагента — скрыт, подпись «Текст сформирован по правилам без языковой модели».
- Ответ валидируется по guardrails G2–G4 (`functional_spec.md` §5); рекомендация под контекст сделки — осознанное исключение из G7 для блока «Краткий вывод» при compare.
