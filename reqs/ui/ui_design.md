# Проект пользовательского интерфейса

**Основание:** `reqs/functional_spec.md` §4–6 (сценарии, guardrails, требования к интерфейсу), `reqs/profile_fields.md` (блоки карточки и зоны отображения), `reqs/signal_rules.md` (полярности, слоты сводки).
**Кликабельный макет:** `mockup.html` в этой папке (открыть в браузере; данные — компании T1–T3 из `functional_spec.md` §10).
**Дизайн-система:** [Alfa Core Components](https://github.com/core-ds/core-components). Ниже каждому элементу сопоставлен пакет `@alfalab/core-components-*`. Для сборки к 07.09 на Gradio дана таблица замен (§9).

---

## 1. Принципы

1. **Сначала вывод, потом данные.** Первый экран после ввода ИНН — сводка из 4–5 фактов и рекомендация. Полный отчёт — в карточке по клику, а не на первом экране.
2. **Цвет принадлежит сигналу, а не компании.** Полярность каждого факта окрашена; сама компания, колонка сравнения и строка в панели сессии цветом не оцениваются. Единственное исключение — метка банка, у которой своя шкала (это оценка банка, не наша).
3. **Пробел виден.** Всё, что оценить нельзя, показано серым пунктирным блоком «Оценить нельзя», а не пустым местом или отсутствием строки.
4. **Каждый факт ведёт к источнику.** Ссылка `[поле]` стоит рядом с фактом и по клику подсвечивает блок карточки.
5. **Без ранжирования.** В сравнении нет итоговой строки, баллов, сортировки по «надёжности» и цветовой шкалы между колонками. Различия перечисляются, выбор оставлен пользователю.
6. **Чат всегда рядом.** Он не отдельный режим, а третья колонка на всех состояниях экрана: любое действие в интерфейсе можно повторить словами и наоборот.

## 2. Информационная архитектура

```
Экран (единственный)
├── A. Панель сессии (слева, 300 px)
│   ├── Ввод ИНН + «Добавить»
│   ├── Список контрагентов (1–5): имя, ИНН, метка банка, удалить
│   ├── Контекст сделки (P2): цель, сумма
│   └── «Доступные ИНН» · «Очистить сессию»
├── B. Рабочая область (центр, растягивается)
│   ├── Вкладки: Сводка · Карточка · Сравнение (при 2+)
│   ├── Сводка — по выбранному контрагенту
│   ├── Карточка — блоки A–F по выбранному контрагенту
│   └── Сравнение — таблица · Различия · Что проверить
└── C. Чат (справа, 380 px)
    ├── История сообщений
    ├── Пресеты вопросов (P2)
    └── Поле ввода
```

Выбранный контрагент — общий для вкладок «Сводка» и «Карточка»; переключение в панели сессии меняет обе. «Сравнение» не зависит от выбора и показывает всех.

## 3. Сетка и размеры

Десктоп, минимальная ширина 1280 px. Три колонки: `300px | 1fr | 380px`, промежутки 16 px, внешние поля 24 px. При ширине < 1280 px чат складывается в нижнюю панель (`bottom-sheet`), панель сессии — в выезжающий `drawer`; мобильная версия в MVP не проектируется.

Вертикальный ритм — токены `--gap-*` из `@alfalab/core-components-vars` (4, 8, 12, 16, 20, 24, 32). Радиусы — `--border-radius-12` для карточек и фактов, `--border-radius-8` для тегов.

Типографика — `typography` пакета: заголовок экрана `headline-system-medium` 20/24, заголовки блоков `headline-system-small` 16/20, основной текст `paragraph-primary-medium` 15/20, вторичный `paragraph-secondary-medium` 13/18, ссылки на поля — моноширинный 12/16.

## 4. Зона A — панель сессии

| Элемент | Компонент | Поведение |
|---|---|---|
| Поле ИНН | `input` (label «ИНН», hint «10 цифр — юрлицо, 12 — ИП», `inputMode="numeric"`) | Enter или кнопка добавляет. Ошибки под полем: «Введите 10 или 12 цифр», «Отчёт по ИНН … не найден», «В сессии не больше 5 контрагентов» (`error` prop) |
| Кнопка «Добавить» | `button` view `primary`, size 48 | Заблокирована при пустом поле; `loading` во время запроса (≤ 3 с) |
| Список контрагентов | `list` из `pure-cell` | Каждая ячейка: краткое имя (1 строка, обрезка), ИНН моноширинным, метка банка `status` (§8.2), крестик `icon-button` для удаления. Активный — фон `bg-secondary` и левая полоса 3 px `text-primary` |
| Счётчик | `typography` secondary | «3 из 5 контрагентов» |
| Контекст сделки (P2) | `select` «Цель проверки» (Без контекста · Поставка · Госзакупка), `amount-input` «Сумма контракта, ₽» | Изменение пересчитывает сводки и сравнение; появляется строка «Соразмерность сделки» |
| «Доступные ИНН» | `button` view `secondary`, открывает `side-panel` | Таблица 100 строк: ИНН, имя, метка банка, тип (ЮЛ/ИП); клик по строке добавляет в сессию. Демо-помощник, в проде отсутствует |
| «Очистить сессию» | `button` view `ghost`, `confirmation` | Сбрасывает контрагентов и историю чата |

Пустая сессия: вместо списка — иллюстративный текст «Добавьте 1–5 контрагентов по ИНН. Сводка появится сразу, сравнение — от двух компаний».

## 5. Зона B — рабочая область

### 5.1. Вкладки

`tabs` view `secondary`, размер `m`. Состав: «Сводка», «Карточка», «Сравнение». Третья вкладка появляется при втором контрагенте и получает фокус автоматически при добавлении второго и последующих; при удалении до одного — исчезает, активной становится «Сводка». Рядом с «Сравнение» — `badge` с числом контрагентов.

Над вкладками — заголовок текущего контрагента (для «Сводка» и «Карточка»): краткое имя, `status` метки банка и ЗСК, «ИНН · ОГРН · действует с дд.мм.гггг · отчёт от дд.мм.гггг». Для «Сравнение» заголовок — «Сравнение N контрагентов».

### 5.2. Сводка

Порядок сверху вниз:

1. **Заголовок-предупреждение** (если есть) — `alert` view `negative`: «Организация не действует», «ФНС приняла решение о предстоящем исключении из ЕГРЮЛ (02.08.2026)», «Организация в процедуре банкротства». Показывается над всеми фактами и не считается фактом.
2. **Факты** — вертикальный список из 4–5 карточек `plate` (без заголовка, `border`, `rounded`). Слева — полоса полярности 4 px и пиктограмма (§8.1), затем название слота мелким текстом («Оценка банка», «Финансы», «Юридические события», «Реестры ФНС», «Дополнительно»), текст факта и ссылки `[поле]` (§8.3). Пятая карточка, если её нет, не рисуется — пустых слотов не бывает.
3. **Оценить нельзя** — `plate` view `custom` с серым пунктирным контуром: «Недостаточно данных для оценки: сведений о проверках в отчёте нет; тренд выручки (данные только за 2025)». Если пробелов нет — плашка не показывается.
4. **Что проверить до сделки** — `plate` view `attention` с заголовком; нумерованный список шагов из `signal_rules.md` §4, у каждого шага в скобках — сигнал-причина мелким текстом. Если сигналов, требующих действий, нет: «Стандартная проверка документов; сигналов, требующих отдельных действий, не выявлено».
5. **Источник текста** — строка `typography` tertiary внизу: «Формулировки уточнены языковой моделью» или «Текст сформирован по правилам без языковой модели» (§7, состояние LLM).

Каждый факт кликабелен: клик переводит на «Карточку» и подсвечивает блок-источник (`underlay` жёлтый на 1,5 с).

### 5.3. Карточка

Шесть блоков в порядке `profile_fields.md`; каждый — `accordion`-секция с заголовком и счётчиком сигналов (например, «Юридические события · 2 сигнала»). По умолчанию раскрыты все, кроме F. Внутри блока — `pure-cell` строками «подпись — значение»; рядом с полями, породившими сигнал, — метка полярности (§8.1) с текстом правила во `tooltip`.

| Блок | Содержимое | Компоненты |
|---|---|---|
| A. Оценка банка | Две строки: «Уровень риска банка» и «ЗСК» с `status`. Подпись: «Метки рассчитаны банком и не пересчитываются» | `status`, `typography` |
| B. Профиль | Полное наименование, ИНН, ОГРН, КПП, статус и дата, дата регистрации и возраст, размер, основной ОКВЭД (код + описание), адрес, email, сайт, телефоны, режим налогообложения, дата отчёта. Пустые — «не указано» tertiary | `pure-cell`, `link` для email/сайта |
| C. Финансы | Виджет `chart` (столбики: выручка и прибыль по годам, две серии; год без выручки подписан «нет данных» и рисуется пустым слотом с подписью, а не нулевым столбиком). Под ним `table`: строки — показатели (Выручка, Прибыль, Капитал и резервы, Краткосрочные обязательства, Оборотные активы), колонки — годы по возрастанию. Коэффициенты (если есть) — отдельная строка. Тренд — `status` рядом с заголовком («+42 % за 2023–2025»). Если `finReports` нет — вместо виджета и таблицы `plate` серая: «Финансовая отчётность в отчёте отсутствует» / «ИП не публикует бухгалтерскую отчётность» | `chart`, `table`, `plate` |
| D. Юридические события | Три подраздела. **Исполнительные производства:** `segmented-control` «Активные (N) · Завершённые (M)», `table` (номер, дата, сумма или «не указана»), `pagination` по 10. **Арбитраж:** сводная `table` роли × статус (завершено / обжаловано / открыто) с суммами, общее число как «всего», роли — «из них»; ниже по годам из `arbitrationCases`. **Проверки:** `table` (орган, форма, даты, результат), `pagination`. Пустые разделы подписаны по типу: «не найдены» или «сведений в отчёте нет» | `segmented-control`, `table`, `pagination` |
| E. Реестры ФНС | Негативные отметки — `plate` view `negative`/`attention` (по полярности правила) с полным текстом банка. Позитивные — `collapse` «Проверено N реестров, отметок нет» → список названий. Коды-дубликаты (`executionProceedings`, `arbitrationDefendant`, `profit`…) показываются здесь как есть с пометкой «дублирует блок C/D» | `plate`, `collapse` |
| F. Дополнительно | Руководитель (ФИО, должность, с даты; метка при смене за 24 мес.), учредители (`table`: имя, доля, с даты), лицензии (`table`: название, статус подписью, даты; истёкшие — `status` red), госзакупки (`table` по годам), дополнительные ОКВЭД (`collapse`), филиалы, связанные компании (P3: `table` имя, ИНН, роль; подпись «риск-профиль связанной компании недоступен») | `table`, `collapse`, `status` |

Кнопка «Показать исходный отчёт (JSON)» — `button` ghost внизу карточки, открывает `side-panel` с деревом полей (P3). Для теста RAT кнопка скрывается флагом.

### 5.4. Сравнение

1. **Таблица** — `table` с фиксированной первой колонкой (критерий) и колонками контрагентов (2–5). Заголовок колонки — краткое имя (клик открывает карточку), ИНН, `status` метки банка. Строки: Оценка банка · Финансы · Юридические события · Реестры ФНС · Полнота данных · (P2) Соразмерность сделки. Ячейка — список фактов с пиктограммой полярности, по одному на строку, порядок `negative → caution → gap → info → positive`. Ячейка «Полнота данных» с пустыми `gaps` — «Все разделы отчёта заполнены» с зелёной галочкой. Нет строки «Итого», нет сортировки, ширина колонок равная.
2. **Различия** — `plate` common с заголовком «Различия»; список строк вида «**Финансы.** Транслориум: выручка растёт (+42 %). Агилар СК: краткосрочные обязательства превышают оборотные активы. Техпром: тренд оценить нельзя». Только те критерии, где полярности или наборы negative/caution отличаются.
3. **Что проверить до сделки** — колонки по контрагентам (`grid`), в каждой `plate` view `attention` с шагами §4 для этого контрагента.
4. Подпись под таблицей: «Порядок колонок — порядок добавления в сессию. Сравнение не ранжирует компании; выбор за вами».

## 6. Зона C — чат

| Элемент | Компонент | Поведение |
|---|---|---|
| Заголовок | `typography` + `status` grey «по данным отчёта» | Напоминание об ограничении источников |
| Лента | контейнер с `scrollbar` | Сообщения пользователя — справа, `plate` common; ответы агента — слева, без плашки, `markdown` |
| Ответ агента | `markdown` + собственный рендер ссылок `[поле]` (§8.3) | Внутри ответов агент использует те же пиктограммы полярности перед фактами; плашка «Недостаточно данных» — серый пунктирный блок как в сводке |
| Действия из чата | `tag` view `outlined` под ответом | Когда агент добавил контрагента или обновил контекст сделки: «Открыть сводку», «Открыть сравнение» |
| Индикатор ответа | `skeleton` три строки | Появляется сразу после отправки; при > 30 с заменяется `system-message` «Языковая модель не ответила; данные доступны в карточке» |
| Пресеты (P2) | горизонтальный ряд `filter-tag`, прокрутка | «Почему такая оценка банка?», «Что с финансами?», «Есть ли долги и суды?», «Чего не хватает в отчёте?», «Что проверить до сделки?», при 2+ — «В чём главные различия?». Клик отправляет текст |
| Поле ввода | `textarea` авторост до 4 строк + `icon-button` отправить | Enter — отправка, Shift+Enter — перенос. Плейсхолдер «Спросите про контрагентов сессии или введите ИНН» |
| Отладка (флаг) | `collapse` под ответом «Проверка ответа: 3 поля, 0 замечаний» | Показывает результат валидатора G3/G4 из `functional_spec.md` §5; включается для демо-слайда о грандинге |

Чат распознаёт ИНН в тексте: если пользователь пишет «проверь 1660266560», агент вызывает инструмент, контрагент появляется в панели сессии, вкладка переключается по правилу §5.1, ответ содержит сводку и тег «Открыть сводку».

## 8. Визуальный язык

### 8.1. Полярность сигнала

| Полярность | Пиктограмма (`cdn-icon`, glyph) | Цвет полосы / иконки (токены `vars`) | Фон карточки факта |
|---|---|---|---|
| `negative` | `alert-circle_m` | `--color-light-status-negative` #ff4837 | `--color-light-bg-negative-muted` #ffebeb |
| `caution` | `exclamation_m` | `--color-light-status-attention` #fa9313 | `--color-light-bg-attention-muted` #ffefd9 |
| `gap` | `question-circle_m` | `--color-light-text-tertiary`, контур пунктиром 1 px | без заливки |
| `info` | `information-circle_m` | `--color-light-text-secondary` | `--color-light-bg-secondary` |
| `positive` | `checkmark-circle_m` | `--color-light-status-positive` #0cc44d | без заливки, зелёная иконка |

Цвет применяется к полосе, иконке и фону факта. К имени компании, к ячейке таблицы целиком, к заголовку колонки — никогда.

### 8.2. Метка банка и ЗСК

`status` view `muted-alt`, `shape="rounded"`, `uppercase={false}`:

| Значение | Подпись | `color` |
|---|---|---|
| `LOW` | риск низкий | `green` |
| `MEDIUM` | риск средний | `orange` |
| `HIGH` | риск высокий | `red` |
| `UNKNOWN` | риск не определён | `grey` |
| `GREEN` | ЗСК зелёный | `green` |
| `YELLOW` | ЗСК жёлтый | `orange` |
| `RED` | ЗСК красный | `red` |

Рядом с меткой во `tooltip`: «Оценка банка по собственной модели. Агент её не пересчитывает». Английские коды в интерфейсе не появляются.

### 8.3. Ссылка на поле

Собственный компонент `FieldRef` поверх `tag` view `muted`, size 32, моноширинный шрифт 12 px, цвет `text-secondary`: `finReports[year=2025].common.proceeds`. При наведении — `tooltip` с человеческой подписью поля («Выручка за 2025») и значением; при клике — переход в «Карточку» и подсветка блока. Длинные пути внутри строки не переносятся, при нехватке места сокращаются посередине (`finReports[…].proceeds`) с полным путём в тултипе. Несколько ссылок на один факт — через запятую внутри одного тега.

### 8.4. Числа и даты

## 9. Реализация к 07.09 на Gradio

Core Components — React; текущий стек интерфейса — Gradio. Таблица показывает, чем заменить каждый элемент в `gr.Blocks`, сохранив поведение. Переход на React с Core Components — после хакатона, макет `mockup.html` служит референсом для обоих вариантов.

| Элемент проекта | Core Components | Gradio |
|---|---|---|
| Три колонки | `grid` | `gr.Row` с `gr.Column(scale=3 / 7 / 4)` |
| Поле ИНН + кнопка | `input`, `button` | `gr.Textbox(max_lines=1)`, `gr.Button(variant="primary")`; ошибки — `gr.Markdown` под полем |
| Список контрагентов | `list` + `pure-cell` + `status` | `gr.Radio` с HTML-метками (имя, ИНН, цветная метка) или `gr.HTML` с кликабельными строками через `gr.State` |
| Вкладки | `tabs` | `gr.Tabs` / `gr.Tab`, видимость «Сравнение» через `gr.update(visible=…)` |
| Факты сводки, плашки | `plate`, `alert` | `gr.HTML` с CSS-классами `.fact.negative` и т. д. (стили из `mockup.html`) |
| Аккордеон карточки | `accordion` | `gr.Accordion` |
| Таблицы | `table`, `pagination` | `gr.Dataframe(interactive=False)` для финансов; `gr.HTML` для сравнения (нужны иконки и переносы) |
| Виджет финансов | `chart` | `gr.BarPlot` с двумя сериями; при отсутствии данных — `gr.Markdown` вместо графика |
| Метки, теги, ссылки на поля | `status`, `tag` | `<span class="status …">`, `<code class="fieldref">` в `gr.HTML`/Markdown |
| Чат | `markdown`, `textarea`, `skeleton` | `gr.Chatbot(type="messages")` + `gr.Textbox` + `gr.Button`; пресеты — `gr.Examples` или ряд `gr.Button(size="sm")` |
| Тултипы | `tooltip` | атрибут `title` в HTML |
| «Доступные ИНН» | `side-panel` | `gr.Accordion(open=False)` с `gr.Dataframe` и обработчиком `select` |
| Подтверждение очистки | `confirmation` | двухшаговая кнопка («Очистить» → «Точно очистить?») |

CSS-переменные цветов из §8 переносятся в `gr.Blocks(css=…)`; шрифт — системный (`--font-family-system`), лицензионные шрифты банка не используются.

## 10. Доступность и мелочи

- Контраст текста на цветных фонах фактов ≥ 4,5:1; полярность передаётся и цветом, и пиктограммой, и словом в тексте факта.
- Все действия доступны с клавиатуры: Enter добавляет ИНН, стрелки переключают контрагентов в списке, Tab обходит вкладки.
- Ошибки ввода — текстом под полем, не только цветом рамки.
- Заголовок страницы — «Проверка контрагентов»; заголовок вкладки браузера меняется на имя выбранного контрагента.
- Тексты интерфейса — на русском; английские слова допустимы только внутри `[поля]` и в JSON исходного отчёта.
