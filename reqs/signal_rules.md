# Правила срабатывания сигналов

Детерминированные условия для кода и для проверки ответов LLM. Поля профиля и зоны отображения — в `profile_fields.md`. Структура отчёта — в `columns_spec.md`. Источник данных MVP — `contractors_audit.snapshot_C12613591.csv` (100 отчётов, 2654 колонки); все цифры срабатываний ниже — по нему. Каждое правило опирается только на колонки, реально присутствующие в CSV.

**Не score, но фиксированный приоритет.** Правила не вычисляют «важность». Они задают, когда факт попадает в вывод, и в каком порядке заполняются слоты сводки (§5). Внутри слота действует фиксированный порядок полярностей: `negative` → `caution` → `gap` → `info` → `positive`. Это осознанное продуктовое решение (риск-факты раньше нейтральных), а не оценка агентом «насколько плохо».

**Факт ≠ пробел.** «Не найдено» (пустой раздел, который банк всегда возвращает) — факт с полярностью `info` или `positive`. Пробел (`gap`) — раздел, которого в отчёте нет и который банк возвращает не всегда. В плоском CSV оба случая выглядят одинаково (все колонки раздела пустые), поэтому трактовка задаётся по разделу: см. `absent`/`notFound` в §2.

## 1. Нормализация данных

CSV — плоская развёртка JSON-отчёта: путь в имени колонки (`report.finReports[0].common.year`), массивы разложены по индексам с фиксированным числом слотов, все значения — строки, пустая строка = значения нет. Код собирает из строки CSV вложенный объект `report` и приводит типы.

| Что | Как в CSV | Нормализация |
|---|---|---|
| Пустая ячейка | `""` | → `null`; элемент массива, у которого все поля пустые, удаляется; раздел, у которого все колонки пустые, считается отсутствующим |
| Даты | ISO-строка `2026-08-18T21:00:00.000Z` — `reportDate`, `registrationDate`, `cofounders[].dateFrom`, `authPerson.positionDate`, `executionProceedings[].date`, `licenses[].issueDate/endDate`, `status.date`; `inspections[].startDate/endDate` — `2023-11-17` | → дата |
| Числа | Строки: `"1567640000"`, `"144853.74"`, `"0.12"` | → число. `executionProceedings[].amount` пуст у 503 из 1305 записей: пустые не суммировать, считать отдельно |
| Булевы | `executionProceedings[].active`, `cofounders[].active` — строки `"true"`/`"false"` | → boolean |
| Слоты массивов | `finReports[0..2]`, `cofounders[0..3]`, `executionProceedings[0..458]`, `inspections[0..47]`, `licenses[0..8]`, `procurements[0..4]`, `reputationalRisks.negative[0..4]`, `positive[0..20]`, `relatedCompanies[0..16]`, `arbitrationCases[0..3]` | Число слотов = максимум по выгрузке; если у компании заполнен последний слот, список мог быть обрезан (в выгрузке — 1 компания с 4 учредителями) |
| Учредитель активен | В `columns_spec.md` поле `isActive`, в CSV — `cofounders[].active` | Читать `active` |
| Арбитраж | Колонки `arbitrationByStatus.*` заполнены у 61 компании; `commonCount` у 61, а суммы по ролям есть не всегда (`pfCount` 44, `pfAmount` 41). У 11 компаний `commonCount` больше суммы `*Count` по ролям | Пустой `*Count` → `0`; `arbTotal` = `commonCount`; в тексте роли перечислять как «из них», не как разбиение |
| Код репутационного фактора | Позитивный код `аrbitrationDefendant` содержит кириллическую «а» (U+0430) | Сравнивать коды после транслитерации кириллицы в латиницу или по словарю |
| Единицы | `finReports` — рубли (`proceeds: 1567640000` — 1,57 млрд ₽) | В текстах — тыс. ₽ / млн ₽ / млрд ₽ с округлением до 1 знака |
| `riskLevel` | `LOW` 85, `MEDIUM` 11, `HIGH` 1, `UNKNOWN` 3 | Отдельное правило `BANK_RISK_UNKNOWN` (gap) |
| `status.reasonName` | Заполнено у 3 компаний со статусом `CURRENT` («предстоящее исключение из ЕГРЮЛ», «изменение места нахождения», «уменьшение уставного капитала») | Читать независимо от `status.status`; правила `STATUS_PENDING_EXCLUSION`, `STATUS_REASON` |
| ИП | 25 из 100 записей — индивидуальные предприниматели: ИНН 12 знаков, нет `finReports`, `foundersInfo`, `taxSystem`, `companySize`, `address`, `kpp` | Признак `isIP`; для ИП отсутствие отчётности и учредителей — норма, тексты gap-правил меняются (см. `FIN_MISSING`) |
| Нет в CSV (есть в `columns_spec.md`) | `baseInfo.staff`, `phones[].phoneType`, `procurements[].tenderAdmittedCnt`, `foundersInfo.parentOrganizations[]`, `inspections[].type` (заполнен у 82 из 224), `licenses[].endDate` (5 из 29) | Правила на них не опираются; в карточке показывать только при наличии |

**Подписи для человека:** `LOW` → «низкий», `MEDIUM` → «средний», `HIGH` → «высокий», `UNKNOWN` → «не определён»; `GREEN` → «зелёный», `YELLOW` → «жёлтый», `RED` → «красный». Коды в скобках не выводить. Отображение YELLOW/RED для ЗСК — открытый вопрос кейсодателю (`columns_spec.md`: банк показывает клиенту Green/grey/grey); до ответа выводим подпись как есть.

## 2. Вспомогательные определения

| Имя | Определение |
|---|---|
| `isIP` | `baseInfo.inn.length === 12` (у юрлиц — 10) |
| `absent(x)` | Все колонки раздела пустые **и** раздел из списка «не всегда возвращается»: `finReports`, `inspections`, `licenses`, `coefficient`, `arbitrationCases`, `foundersInfo`, `taxSystem`, `reputationalRisks`. Это пробел данных |
| `notFound(x)` | Все колонки раздела пустые **и** раздел из списка «банк возвращает всегда, пустой = ничего не найдено»: `executionProceedings`, `arbitrationByStatus`, `procurements`, `relatedCompanies`. Это факт «не найдено». Список разделов — допущение, вынесено вопросом кейсодателю (`context_pack.md` §7) |
| `reportDate` | Дата из `reportDate`; если нет — `_id.date` |
| `finSorted` | `finReports`, отсортированные по `common.year` по возрастанию (в CSV не отсортированы у 68 из 69) |
| `finWindow` | Последние 3 записи `finSorted` с непустым `common.year` (в CSV максимум 3 слота) |
| `hasProceeds(f)` | `f.common.proceeds` — число и `≠ 0` |
| `hasProfit(f)` | `f.common.profit` — число (заполнен в 100 из 202 годовых записей; `0` допустим) |
| `proceedsYears` | Записи `finWindow`, где `hasProceeds` |
| `profitYears` | Записи `finWindow`, где `hasProfit` |
| `finLast` | Последняя запись `finWindow` |
| `pctChange(old, new)` | `(new - old) / abs(old)`; применяется только к `proceedsYears`, где `old ≠ 0` гарантированно |
| `TREND_THRESHOLD` | `0.05` (5%) — граница роста/падения vs стагнации |
| `RECENT_MONTHS` | `24` — окно «недавней» смены учредителя/руководителя |
| `INCEPTION_DAYS` | `30` — если дата назначения/вхождения в пределах 30 дней от `registrationDate`, это не смена, а основание компании |
| `isRecentChange(date)` | `date` не пусто, `(reportDate - date) <= RECENT_MONTHS` месяцев **и** `abs(date - registrationDate) > INCEPTION_DAYS` |
| `activeEP` | Элементы `executionProceedings[]` с `active === true` (в CSV 51 активное из 1305) |
| `epSum`, `epNoAmount` | Сумма `amount` по `activeEP`, где число; количество `activeEP` с пустым `amount` |
| `dpCount`, `ppCount` | `defandantArbitrationPending.dpCount`, `plaintiffArbitrationPending.ppCount` (пусто → 0) |
| `defendantTotal` | `dfCount + daCount + dpCount` |
| `plaintiffTotal` | `pfCount + paCount + ppCount` |
| `arbTotal` | `commonCount`, если есть; иначе `defendantTotal + plaintiffTotal` |
| `violationInspections` | `inspections[]` с `inspectionStatus === "InspectionsViolationDetected"` (точное сравнение; в CSV: `InspectionsViolationNotDetected` 214, `InspectionsUnknownResult` 9, `InspectionsViolationDetected` 1) |
| `negCodes`, `posCodes` | Множества `code` из `reputationalRisks.negative[]` / `positive[]` после нормализации |
| `dealContext` | Контекст сделки из сессии: `goal` (например `procurement`), `amount` — второй эшелон MVP |

## 3. Правила

Колонки: «Что проверяем и зачем» — смысл проверки для человека (какие атрибуты отчёта смотрим и что это говорит о контрагенте); `IF` — формальное условие для кода; `summary` — может занять слот сводки (§5); `compare` — строка таблицы сравнения; `card` — всегда ✓, не показана.

### 3.1. Банк и статус

| ID | Что проверяем и зачем | Полярность | IF | Поля | Текст | summary | compare |
|---|---|---|---|---|---|:---:|:---:|
| `STATUS_CLOSED` | Статус в ЕГРЮЛ и причина закрытия. С ликвидированной организацией договор заключить нельзя; это первое, что нужно знать | negative | `status.status === "CLOSED"` (в CSV — 0, все 100 `CURRENT`) | `status.status`, `status.reasonName` | «Организация не действует ({reasonName}).» | заголовок | ✓ |
| `STATUS_PENDING_EXCLUSION` | Компания действует, но ФНС уже приняла решение исключить её из ЕГРЮЛ как недействующую. Через несколько месяцев юрлица не станет; договор с ней — договор с исчезающим контрагентом | negative | `status.status === "CURRENT"` и `status.reasonName` содержит «предстоящем исключении» (1 компания) | `status.reasonName`, `status.date` | «ФНС приняла решение о предстоящем исключении из ЕГРЮЛ ({date}).» | заголовок | ✓ |
| `STATUS_REASON` | У действующей компании в ЕГРЮЛ идёт процедура: смена адреса, уменьшение уставного капитала и т.п. Само по себе не риск, но уменьшение капитала затрагивает права кредиторов, а смена адреса — реквизиты в договоре | caution | `status.status === "CURRENT"`, `reasonName` не пуст и не сработал `STATUS_PENDING_EXCLUSION` (2 компании) | `status.reasonName`, `status.date` | «В ЕГРЮЛ идёт процедура: {reasonName} ({date}).» | ✓ | ✓ |
| `BANK_RISK` | Итоговая риск-метка банка по своей модели. Отправная точка оценки; агент её не пересчитывает, а объясняет фактами ниже | info | `riskLevel ∈ {LOW, MEDIUM, HIGH}` | `baseInfo.riskLevel` | «Оценка банка: риск {label}.» | ✓ | ✓ |
| `BANK_RISK_UNKNOWN` | Метка банка не рассчитана. Пользователь должен знать, что главного ориентира нет, и не принимать отсутствие метки за «низкий риск» | gap | `riskLevel === "UNKNOWN"` или `absent` | `baseInfo.riskLevel` | «Оценка банка: уровень риска не определён.» | ✓ | ✓ |
| `BANK_ZSK` | Метка «Знай своего клиента» (ЦБ/банк): признаки сомнительных операций. Дополняет риск-метку: компания может быть финансово здорова, но с жёлтой ЗСК | info | `zskRiskLevel` не `absent` | `zskRiskLevel` | «ЗСК: {label}.» | ✓ | ✓ |

`BANK_RISK`/`BANK_RISK_UNKNOWN` и `BANK_ZSK` выводятся одной строкой сводки: «Оценка банка: риск низкий, ЗСК зелёный.» `STATUS_REASON` попадает в слот 5 (§5).

### 3.2. Финансы

| ID | Что проверяем и зачем | Полярность | IF | Поля | Текст | summary | compare |
|---|---|---|---|---|---|:---:|:---:|
| `FIN_MISSING` | Есть ли в отчёте бухгалтерская отчётность вообще. Без неё нельзя судить о масштабе и устойчивости бизнеса; для ИП это норма, для юрлица — повод запросить отчётность напрямую | gap | `absent(finReports)` (31 компания: 25 ИП + 6 юрлиц) | `finReports` | Юрлицо: «Финансовая отчётность в отчёте отсутствует — оценить финансы нельзя.» ИП: «ИП не публикует бухгалтерскую отчётность — оценить финансы по отчёту нельзя.» | ✓ | ✓ |
| `FIN_EMPTY` | Отчётность есть, но выручка и прибыль по всем годам пустые или нулевые. Формально компания сдаёт отчётность, фактически оценить обороты невозможно (нулевая отчётность или неполная выгрузка) | gap | `finReports` есть, но `proceedsYears` и `profitYears` пусты (6 компаний) | `finReports[].common` | «Отчётность за {y1}–{y2} без показателей выручки и прибыли — оценить финансы нельзя.» | ✓ | ✓ |
| `FIN_TREND_INSUFFICIENT` | Выручка известна только за один год. Масштаб видно, динамику (растёт или сворачивается бизнес) — нет | gap | `proceedsYears.length === 1` (10 компаний) | `finReports[].common.proceeds` | «Выручка есть только за {year} ({value}); тренд оценить нельзя.» | ✓ | ✓ |
| `FIN_PROCEEDS_DOWN` | Выручка за период из 2–3 лет упала более чем на 5%. Сжатие бизнеса повышает риск неисполнения обязательств и задержек | negative | `proceedsYears.length >= 2` и `pctChange(first, last) < -TREND_THRESHOLD` | `common.proceeds`, `common.year` | «Выручка снижается: {v1} ({y1}) → {v2} ({y2}), {pct}%.» | ✓ | ✓ |
| `FIN_PROCEEDS_UP` | Выручка выросла более чем на 5%. Бизнес развивается, объём заказов растёт | positive | `proceedsYears.length >= 2` и `pctChange > TREND_THRESHOLD` | то же | «Выручка растёт: {v1} ({y1}) → {v2} ({y2}), +{pct}%.» | ✓ | ✓ |
| `FIN_PROCEEDS_FLAT` | Изменение выручки в пределах ±5%. Ни роста, ни спада; нейтральный факт для контекста | info | `proceedsYears.length >= 2` и `pctChange ∈ [-T, T]` | то же | «Выручка стабильна: {v1} ({y1}) → {v2} ({y2}).» | ✓ | ✓ |
| `FIN_PROFIT_LOSS` | Чистый результат за последний отчётный год отрицательный. Убыточная компания живёт на займы или капитал; при затяжном убытке растёт риск неплатежей | negative | `hasProfit(finLast)` и `finLast.common.profit < 0` | `common.profit` | «Убыток за {year}: {amount}.» | ✓ | ✓ |
| `FIN_PROFIT_DOWN` | Прибыль за период снизилась. Даже при росте выручки падение прибыли означает рост издержек или демпинг | negative | `profitYears.length >= 2` и `profit_last < profit_first` и `abs(profit_last - profit_first) > 0.05 * abs(profit_first)` | `common.profit` | «Прибыль снижается: {v1} ({y1}) → {v2} ({y2}).» | ✓ | ✓ |
| `FIN_PROFIT_UP` | Прибыль за период выросла. Бизнес не только растёт, но и зарабатывает | positive | `profitYears.length >= 2` и `profit_last > profit_first` и та же граница 5% | то же | «Прибыль растёт: {v1} ({y1}) → {v2} ({y2}).» | ✓ | ✓ |
| `FIN_NEGATIVE_CAPITAL` | Раздел баланса «Капитал и резервы» ниже нуля: накопленные убытки съели уставный капитал, долги больше активов. Признак предбанкротного состояния | negative | `finLast.liabilities.capitals` — число `< 0` | `liabilities.capitals` | «Отрицательный собственный капитал: {amount} ({year}).» | ✓ | ✓ |
| `FIN_DEBT_LOAD` | Краткосрочные долги (до года) против оборотных активов (деньги, запасы, дебиторка). Если долги больше, компании нечем платить по текущим обязательствам без новых займов; риск для предоплаты | negative | `finLast.liabilities.shortTermLiabilities.total` и `finLast.assets.currentAssets.total` — числа, первое `>` второго | оба поля | «Краткосрочные обязательства ({stl}) превышают оборотные активы ({ca}) за {year}.» | ✓ | ✓ |

Для тренда `first`/`last` берутся из `proceedsYears` (для прибыли — из `profitYears`), не из крайних записей окна: год с нулевой или отсутствующей выручкой в сравнение не попадает. Для прибыли процент не выводим (переходы через ноль делают его бессмысленным), только абсолютные значения. На CSV тренд выручки вычислим у 50 компаний; убыток за последний год у 3, отрицательный капитал у 6, долговая нагрузка у 9.

### 3.3. Юридические события

| ID | Что проверяем и зачем | Полярность | IF | Поля | Текст | summary | compare |
|---|---|---|---|---|---|:---:|:---:|
| `EP_ACTIVE` | Незакрытые исполнительные производства ФССП: суд уже присудил долг, а компания его не выплатила. Прямое свидетельство неплатежей; сумма показывает масштаб, а число ИП без суммы — что реальный долг может быть больше | negative | `activeEP.length > 0` (15 компаний) | `executionProceedings[].active`, `amount` | «Активные исполнительные производства: {count} на {epSum}» + при `epNoAmount > 0`: «; по {n} сумма не указана» | ✓ | ✓ |
| `EP_HISTORY_ONLY` | ИП были, но все закрыты. Компания доводила споры до приставов, однако долги погасила; контекст, не риск | info | `executionProceedings.length > 0` и `activeEP.length === 0` (28 компаний) | `executionProceedings[]` | «Исполнительные производства: {count} завершённых, активных нет.» | ✓ | ✓ |
| `EP_NONE` | В базе ФССП ничего не найдено. Компания не доводила долги до принудительного взыскания | positive | `notFound(executionProceedings)` (57 компаний) | `executionProceedings` | «Исполнительные производства не найдены.» | ✓ | ✓ |
| `EP_MISSING` | Раздел ИП в отчёте отсутствует. Не путать с «не найдено»: проверка по ФССП не проводилась или не попала в выгрузку | gap | Колонок раздела нет в файле (в текущем CSV не срабатывает: раздел в списке `notFound`) | `executionProceedings` | «Сведений об исполнительных производствах в отчёте нет.» | ✓ | ✓ |
| `ARB_DEFENDANT_OPEN` | Текущие арбитражные дела, где компанию судят (ответчик). К ней сейчас есть денежные претензии контрагентов или госорганов; сумма — потенциальный отток денег | negative | `dpCount > 0` (10 компаний) | `defandantArbitrationPending.dpCount`, `dpAmount` | «Открытые арбитражные дела как ответчик: {dpCount} на {dpAmount}» (`dpAmount` пуст у 2 из 10 — тогда без суммы) | ✓ | ✓ |
| `ARB_DEFENDANT_DOMINANT` | Соотношение ролей за всю историю: компанию чаще судят, чем она судится сама (минимум 2 дела как ответчик). Открытых дел нет, но паттерн неисполнения обязательств есть | caution | `defendantTotal >= 2` и `defendantTotal > plaintiffTotal` и не сработал `ARB_DEFENDANT_OPEN` (13 компаний) | `arbitrationByStatus` | «Арбитраж: как ответчик {def} дел, как истец {pl}.» | ✓ | ✓ |
| `ARB_SUMMARY` | Арбитраж есть, но без открытых дел как ответчик и без перевеса в роли ответчика. ### 3.4. Реестры ФНС и репутационные факторы

Блок `reputationalRisks` в CSV — это результат прогона по реестрам (у всех 100 компаний; до 21 позитивной и до 5 негативных записей). Работаем по `code`, а не по `name`: тексты банка длиной 150–300 символов в сводку не помещаются, показываем их только в карточке по клику.

**Коды-дубликаты** — исключены из сводки и сравнения, потому что тот же факт даёт правило из §3.2–3.3 или блок F: `executionProceedings`, `arbitrationDefendant`, `inspectionWithViolation`, `profit`, `proceeds`, `currentAssets`, `uncurrentAssets`, `relatedCompanies`, `governmentContract`, `webSite`, `licenses`, `branchesInfo`. В карточке они видны в исходном виде.

`isRecentChange` исключает даты, совпадающие с регистрацией: у молодых компаний `dateFrom` и `positionDate` равны `registrationDate`, и без этого правило дублировало бы `YOUNG_COMPANY` ложным «смена учредителей». Список 41/42/43/49 давал бы на CSV 17 ложных срабатываний из 100: строительство лицензий не требует (СРО, которого в отчёте нет), из 49 лицензируется только пассажирский транспорт. Возврат возможен после согласования списка с кейсодателем.

## 4. Сигнал → следующий шаг

Рекомендация — единственная часть сводки, где LLM формулирует свободно. Чтобы она была проверяемой и одинаковой между сессиями, LLM выбирает из таблицы по сработавшим правилам и переформулирует под контекст, но не придумывает новых действий. Вердикт «не работать» запрещён при любом наборе сигналов.

| Сигнал | Рекомендуемый шаг | Зачем этот шаг |
|---|---|---|
| `STATUS_CLOSED`, `STATUS_PENDING_EXCLUSION`, `REG_BANKRUPTCY` | Уточнить статус в ЕГРЮЛ/ЕФРСБ до любых переговоров | Данные отчёта могли устареть; если статус подтвердится, договор с таким лицом либо невозможен, либо его исполнение зависит от арбитражного управляющего или сроков исключения из ЕГРЮЛ |
| `STATUS_REASON` | Запросить свежую выписку ЕГРЮЛ и уточнить, что за процедура идёт | Смена адреса меняет реквизиты договора; уменьшение уставного капитала даёт кредиторам право требовать досрочного исполнения, и стоит понимать, зачем оно проводится |
| `EP_ACTIVE` | Запросить подтверждение погашения или справку ФССП; учесть сумму в условиях оплаты | Активный долг могут списать со счёта контрагента в любой момент, в том числе из вашей предоплаты; если долг уже погашен, а база ФССП не обновилась, контрагент это подтвердит |
| `ARB_DEFENDANT_OPEN`, `ARB_DEFENDANT_DOMINANT` | Посмотреть предмет открытых дел в картотеке арбитражных дел; уточнить у контрагента | В отчёте только число и сумма; важно, кто истец (поставщик, покупатель, налоговая) и о чём спор: неоплата, качество, срыв сроков. Это показывает, какой именно риск повторится с вами |
| `REG_FNS_BLOCKING` | Запросить справку об отсутствии задолженности; не работать по предоплате до снятия блокировки | При заблокированном счёте контрагент физически не сможет вернуть аванс или оплатить поставку; справка ФНС покажет, снята ли блокировка |
| `REG_INVALID_ADDRESS`, `REG_MASS_ADDRESS`, `REG_INVALID_REG_DATA` | Подтвердить фактический адрес и реквизиты (договор аренды, выписка ЕГРЮЛ) | Компания с недостоверным адресом может быть исключена из ЕГРЮЛ; для претензий и суда нужен адрес, по которому её реально найти |
| `REG_MASS_AUTHPERSON`, `REG_INVALID_AUTHPERSON`, `REG_DISQUALIFIED` | Запросить документы о полномочиях подписанта | Договор, подписанный номинальным или дисквалифицированным лицом, могут признать незаключённым; решение о назначении и паспорт директора закрывают этот риск |
| `FIN_MISSING`, `FIN_EMPTY`, `FIN_TREND_INSUFFICIENT` | Юрлицо: запросить бухгалтерскую отчётность за 2–3 года напрямую. ИП: запросить налоговую декларацию или выписку по счёту за период | Без данных о масштабе бизнеса нельзя понять, соразмерна ли ему сделка; отказ предоставить отчётность сам по себе информативен |
| `FIN_PROFIT_LOSS`, `FIN_NEGATIVE_CAPITAL`, `FIN_DEBT_LOAD`, `FIN_PROCEEDS_DOWN` | Рассмотреть постоплату или обеспечение; запросить пояснения по отчётности | Финансово слабый контрагент чаще задерживает поставку или не возвращает аванс; постоплата, банковская гарантия или залог переносят риск с вас на него |
| `DEAL_AMOUNT_DISPROPORTION` | Разбить сделку на этапы или запросить обеспечение | Контракт больше годового оборота компания может не потянуть по ресурсам; этапная оплата ограничивает потери одним этапом |
| `YOUNG_COMPANY` | Запросить рекомендации/портфолио; начать с небольшого объёма | Истории исполнения обязательств в открытых данных ещё нет; заменить её могут отзывы клиентов и пробная сделка |
| `FOUNDER_RECENT`, `AUTH_PERSON_RECENT` | Уточнить причины смены; проверить полномочия нового руководителя | Смена владельца или директора перед сделкой — типичный шаг при продаже фирмы или уходе от обязательств; выписка ЕГРЮЛ подтвердит, что новый руководитель уже внесён |
| `INSPECTION_VIOLATION` | Запросить акты проверок и сведения об устранении | Нарушение может касаться именно предмета сделки (качество, безопасность, лицензионные требования) и привести к приостановке деятельности контрагента |
| `LICENSE_EXPIRED` | Запросить действующую лицензию до подписания | Работы по истёкшей лицензии незаконны, договор рискует оказаться недействительным, а результат — не принятым надзорным органом |
| Только info/positive и `REG_CLEAN` | Стандартная проверка документов; сигналов, требующих отдельных действий, не выявлено | Данные отчёта не дают повода для дополнительных проверок; остаётся обычная процедура (устав, выписка, полномочия подписанта) |

## 5. Сборка risk summary

Сводка — до 5 фактов плюс рекомендация. Заголовок и слоты фиксированы; внутри слота первое сработавшее правило в порядке полярностей (см. преамбулу) и в порядке перечисления.

| Слот | Правила (первое сработавшее) |
|---|---|
| 0. Заголовок (вне лимита) | `STATUS_CLOSED` или `STATUS_PENDING_EXCLUSION`, если сработал |
| 1. Оценка банка | `BANK_RISK` / `BANK_RISK_UNKNOWN` + `BANK_ZSK` — одна строка |
| 2. Финансы | `FIN_PROCEEDS_DOWN`, `FIN_PROFIT_LOSS`, `FIN_NEGATIVE_CAPITAL`, `FIN_DEBT_LOAD`, `FIN_PROFIT_DOWN`, `FIN_MISSING`, `FIN_EMPTY`, `FIN_TREND_INSUFFICIENT`, `FIN_PROCEEDS_FLAT`, `FIN_PROCEEDS_UP`, `FIN_PROFIT_UP` |
| 3. Юридические события | `EP_ACTIVE`, `ARB_DEFENDANT_OPEN`, `INSPECTION_VIOLATION`, `ARB_DEFENDANT_DOMINANT`, `EP_MISSING`, `ARB_MISSING`, `EP_HISTORY_ONLY`, `ARB_SUMMARY`, `EP_NONE`, `ARB_NONE` |
| 4. Реестры ФНС | все сработавшие `REG_*` negative/caution одной строкой; иначе `REG_MISSING`; иначе `REG_CLEAN` |
| 5. Дополнительно | `DEAL_AMOUNT_DISPROPORTION`, `LICENSE_EXPIRED`, `STATUS_REASON`, `YOUNG_COMPANY`, `AUTH_PERSON_RECENT`, `FOUNDER_RECENT`, `PROCUREMENT_WIN`† |

Слоты 1–4 заполняются всегда (у каждого есть gap- или info-fallback), то есть база — 4 факта. Пятый факт — первое из: второе сработавшее `negative` правило слота 3; второе сработавшее `negative` слота 2; слот 5. Если ничего из этого нет, сводка из 4 фактов.

Правило для LLM: в текст попадают только `summary_slots`; факты вне слотов доступны в карточке и Q&A. Формулировку можно сгладить (склонения, «1 год / 2 года»), числа и годы — как в `message`.

## 6. Формат результата для кода

```json
{
  "inn": "7826131151",
  "signals": [
    {
      "id": "FIN_DEBT_LOAD",
      "polarity": "negative",
      "fields": [
        "finReports[year=2025].liabilities.shortTermLiabilities.total",
        "finReports[year=2025].assets.currentAssets.total"
      ],
      "message": "Краткосрочные обязательства (12,4 млн ₽) превышают оборотные активы (8,1 млн ₽) за 2025.",
      "zones": ["summary", "compare", "card"]
    },
    {
      "id": "REG_CLEAN",
      "polarity": "positive",
      "fields": ["reputationalRisks.positive[]"],
      "message": "Проверено 14 реестров ФНС, негативных отметок нет.",
      "zones": ["summary", "compare", "card"]
    }
  ],
  "gaps": ["INSPECTION_MISSING"],
  "summary_slots": ["BANK_RISK", "FIN_DEBT_LOAD", "EP_NONE", "REG_CLEAN", "YOUNG_COMPANY"],
  "next_steps": ["FIN_DEBT_LOAD", "YOUNG_COMPANY"]
}
```

Индексация `finReports[year=2025]` — по году, не по позиции в массиве (в CSV записи не отсортированы; позиция `finReports[0]` в колонке ничего не говорит о годе). `gaps` — все сработавшие правила с полярностью `gap`, независимо от попадания в сводку; из них строится колонка «полнота данных». `next_steps` — ID правил, по которым LLM берёт рекомендации из §4.

LLM получает `signals`, `summary_slots`, `next_steps` и формулирует текст; не добавляет факты, не покрытые сработавшими правилами, и не выбирает действия вне §4.
